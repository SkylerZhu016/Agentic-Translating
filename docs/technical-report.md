# Agentic Translating vNext 技术报告

## 摘要

本项目面向文学、诗歌、规范文本、学术技术文本等高难度双向翻译——这些领域没有单一标准答案。系统不把多个 Agent 当作独立任务的并行执行器，而是将它们视为针对同一问题的不同视角的候选生成器。主 Agent 负责选角、比较、审议、融合和版本化修改。核心方法 FSBP 由自由文本、阶段正文语义契约、最后一个独立 `---` 边界、raw 留档、body-only 继承与注释隔离共同组成，在保留自由表达的同时阻断候选自我解释向下游传播。

vNext 新增 10 个原型、20 个中英方向变体、双向提示词包、动态/固定组队、两条成稿路径、证据化编辑、revision 预设、批量队列、历史恢复、Windows Electron 与 Docker 自部署，并修复了上下文截断、多端点快照和密钥泄露边界。

## 1. 问题定义

翻译涉及多义解析、目标语自然度、作者声音、文化负载、术语一致性、长距离连贯和形式约束等多个维度。单一模型的一次输出往往将这些目标折合成一个未经比较的妥协方案。多模型和多提示词能扩大候选空间，但如果缺少可审计的融合过程，用户仍然无法回答"为什么改成这样、依据来自哪里"。

本项目因此同时解决三个问题：

1. 如何低成本地产生有意义的候选差异，而非随机的变化；
2. 如何让审议过程接收完整证据，又不被候选注释锚定；
3. 如何把最终修改保存为可查看、可撤销、可复现的版本历史。

## 2. 方法

### 2.1 角色化候选

10 个原型覆盖基础、表达、领域、创意和对抗视角。主 Agent 的常驻上下文仅包含简短目录，调用时才注入角色的完整提示词。后端保证至少两个不同原型的成功候选，当动态选择失效时执行"忠实 + 自然"的保底策略。

### 2.2 FSBP

模型返回完整的自由文本。系统保存 raw 内容，解析出正文 body 与 annotation，所有后续 Agent 只接收 body。协议不规定固定字段，但规定阶段正文的用途：审查正文承载错误与风险证据，筛选正文承载保留与修补决定，编排正文承载完整工作译文，组装正文承载正式译文。过程说明与自我评价进入 annotation。精确的状态变更仍由少量工具 JSON 完成。

### 2.3 双向提示词

英译中的编排链使用中文提示词，中译英链使用英文提示词；用户任务要求原样作为用户数据处理。方向和提示词包在会话创建时冻结，不能原地反转。

### 2.4 证据化编辑

`write_draft` 需要至少两个候选 invocation。`replace_text` 校验当前版本、唯一匹配和事务一致性，创建 Patch 与不可变的新版本。Unicode grapheme 差异用于界面标记，失败时退化为块级对照。

## 3. 系统设计

服务端拥有运行任务，SSE 只是可重连的订阅通道。事件带递增序号并落库，浏览器离开不会取消运行；启动时遗留的 running 标记被置为 interrupted。配置快照冻结实际的端点与模型绑定，公共 DTO 只暴露端点摘要和 `hasApiKey`。

SQLite 保存会话、候选 raw/body/annotation、阶段输出、工具事件、版本、Patch、草稿、预设 revision 与批次。旧 schema 保留只读兼容，迁移不做破坏性删除。

## 4. 产品交互

顶栏方向开关不增加导航层级。当存在非空草稿或现有会话时，切换弹窗明确说明旧进度已保存；"不再提示"只在确认切换时持久化。两个方向各有一个 SQLite 草稿。

新增界面复用既有 Card、Badge、Modal、Button、Textarea 和纸墨色板。候选与最终卡片仅增加紧凑证据 Badge、展开详情和修订对照，不改动主体双栏骨架。

## 5. 确定性检查

后端检查段落/分节、非空行、必需/禁用词、结构、数字、单位和专名遗漏提示。诗歌额外提供：

- 英译中：汉字数、五七言倾向、末字与普通话拼音韵母；明确不等同于平水韵裁决。
- 中译英：行数、词数、末词与 CMU 词典近似韵脚；未知专名标为未知，仅作现代英语发音辅助。

检查器不修改、不拒绝候选，只将自然语言证据交给审议 Agent。

## 6. FSBP 验证计划

早期试运行使用的样本、执行器和结果已经退役，不能作为新版架构的质量
证据。新版验证在 `FSBP_Test/` 中重新建立，并将三个问题分开：

1. JSON 与 FSBP 的协议可靠性；
2. raw 与 body-only 的注释隔离效果；
3. 直接翻译、多 Agent raw、多 Agent FSBP 的端到端质量。

数据集计划包含 8 个开发样本和 24 个锁定测试样本，按方向及四类高难文本
均衡。注释压力样本只能来自正常调用中自然出现并经人工确认的实际错误，
不得人工编造误导注释。具体文本尚未确认，因此当前不报告实验结果或质量
增益。

## 7. 威胁与局限

- 模型裁判可能偏好自身的文风，交换顺序只能缓解位置偏差，无法彻底消除。
- 公有领域与开放许可要求会造成一定年代偏差，数据集也不能代表全部语种与领域。
- FSBP 能隔离显式 annotation，但无法识别正文中伪装成译文的元指令。
- token 估算并非各供应商的精确 tokenizer；未配置 contextWindow 时只能发出警告。
- 拼音韵母和 CMU 近似韵脚不具备古典或诗学权威性。
- 法律/医学等领域的输出不能替代专业审查。

## 8. 工程完整度

本轮交付将原型扩展为包含数据迁移、协议、双向 Agent、服务端编排、审计版本、批处理、桌面发行、自部署和数据集校验工具的完整系统。最终质量门禁以 `typecheck`、Vitest、Next build、Playwright、Windows 打包与 Docker 健康检查为准；实际执行状态应以开发交付记录为准，不在报告中预先宣称通过。
