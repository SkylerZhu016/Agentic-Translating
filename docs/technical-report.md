# Agentic Translating vNext 技术报告

## 摘要

本项目面向文学、诗歌、规范文本、学术技术文本等没有单一标准答案的高难度双向翻译。系统不把多 Agent 当作独立任务并行器，而把它们当作同题不同视角的候选生成器；主 Agent 负责选角、比较、审议、融合和版本化修改。核心方法 FSBP 使用首个独立 `---` 将正文和注释分离，在保留自由表达的同时阻断注释向下游传播。

vNext 新增 10 个原型、20 个中英方向变体、双向提示词包、动态/固定组队、两个成稿路径、证据化编辑、revision 预设、批量队列、历史恢复、Windows Electron 与 Docker 自部署，并修复上下文截断、多端点快照和密钥泄露边界。

## 1. 问题定义

翻译包含多义解析、目标语自然度、作者声音、文化负载、术语一致性、长距离连贯和形式约束。单一模型的一次结果常会把这些目标折成一个未经比较的折中。多模型和多提示词能扩大候选空间，但如果缺少可审计的融合过程，用户仍然无法回答“为什么改成这样、依据来自哪里”。

本项目因此同时解决三个问题：

1. 如何低成本地产生有意义而非随机的候选差异；
2. 如何让审议过程接收完整证据又不被候选注释锚定；
3. 如何把最终修改保存为可查看、可撤销、可复现的版本历史。

## 2. 方法

### 2.1 角色化候选

10 个原型覆盖基础、表达、领域、创意和对抗视角。主 Agent 常驻上下文只含短目录，调用时才注入角色完整提示词。后端保证至少两个不同原型的成功候选，动态选择失效时执行“忠实 + 自然”保底。

### 2.2 FSBP

模型返回完整自由文本。系统保存 raw，解析正文 body 与 annotation，所有后续 Agent 只接收 body。该协议没有恢复产品内的严格 JSON，也不要求固定字段。精确状态变更仍由少量工具 JSON 完成。

### 2.3 双向提示词

英译中编排链使用中文，中译英链使用英文；用户任务要求原样作为用户数据。方向和提示词包在会话创建时冻结，不能原地反转。

### 2.4 证据化编辑

`write_draft` 需要至少两个候选 invocation。`replace_text` 校验当前版本、唯一匹配和事务一致性，创建 Patch 与不可变新版本。Unicode grapheme 差异用于界面标记，失败时退化为块级对照。

## 3. 系统设计

服务端拥有运行任务，SSE 只是可重连订阅。事件带递增序号并落库，浏览器离开不会取消运行；启动时遗留 running 标记 interrupted。配置快照冻结实际端点与模型绑定，公共 DTO 只暴露端点摘要和 `hasApiKey`。

SQLite 保存会话、候选 raw/body/annotation、阶段输出、工具事件、版本、Patch、草稿、预设 revision 与批次。旧 schema 保留只读兼容，迁移不做破坏性删除。

## 4. 产品交互

顶栏方向开关不增加导航层级。非空草稿或现有会话切换时，弹窗明确说明旧进度已保存；“不再提示”只在确认切换时持久化。两个方向各有一个 SQLite 草稿。

新增界面复用既有 Card、Badge、Modal、Button、Textarea 和纸墨色板。候选与最终卡片只增加紧凑证据 Badge、展开详情和修订对照，不改动主体双栏骨架。

## 5. 确定性证据

后端检查段落/分节、非空行、必需/禁用词、结构、数字、单位和专名遗漏提示。诗歌额外提供：

- 英译中：汉字数、五七言倾向、末字与普通话拼音韵母；明确不等同于平水韵裁决。
- 中译英：行数、词数、末词与 CMU 词典近似韵脚；未知专名标未知，仅作现代英语发音辅助。

检查器不修改、不拒绝候选，只把自然语言证据交给审议 Agent。

## 6. 协议消融实验

仓库提供可中断续跑的 CLI，固定 20 个公共领域样本（两个方向各 10，含诗歌与散文）和 6 个误导性注释压力样本。三个候选模型的初稿只生成一次并冻结，三组共享候选：

1. `strict-json`：阶段严格 JSON，格式失败允许一次修复；
2. `freeform-raw`：自由文本，注释继续传给下游；
3. `fsbp-v1`：自由文本，仅正文传给下游。

协调模型、阶段目标和采样参数一致。独立裁判匿名排序，并以逆序再次评估。运行记录包含格式成功、重试、阶段完成、延迟、token、评分和失败原因；报告计算胜率、Wilson 95% 区间和成对符号检验。

### 6.1 首次真实运行

运行 `2026-07-24T15-25-09-239Z-e5ee2aaa` 使用三个候选模型、一个协调模型和一个独立裁判模型，完成了 20 个公共领域样本（其中 6 个带误导性注释压力条件）。共保存 60 次冻结候选、240 次阶段调用和 40 次交换候选顺序的匿名裁判评估；没有调用或阶段失败。三组阶段完成率与最低诗行结构满足率均为 100%。`strict-json` 发生 1 次格式修复重试，两个自由文本协议均为 0 次。

两次顺序评估按原文样本聚合后，12 个样本得到唯一首选，8 个并列。样本级唯一首选胜率为：

- `strict-json`：33.3%，Wilson 95% CI 13.8%–60.9%；
- `freeform-raw`：41.7%，Wilson 95% CI 19.3%–68.0%；
- `fsbp-v1`：25.0%，Wilson 95% CI 8.9%–53.2%。

全部成对符号检验均未达到统计显著。6 个压力样本中，唯一首选分别为 `strict-json=1`、`freeform-raw=2`、`fsbp-v1=1`，另有 2 个并列。因此，这次小样本自动评测**没有证明 FSBP 的译文质量优于两个对照组，也没有确认注释隔离会在当前压力设计下提高裁判偏好**。这是负结果，不应改写成支持性结论。

FSBP 在本次运行中的阶段 token 为 118,719，低于 `strict-json` 的 153,619 和 `freeform-raw` 的 155,766；相对两者分别减少约 22.7% 和 23.8%。但它的平均阶段延迟为 22.0 秒，快于 `freeform-raw` 的 25.1 秒、慢于 `strict-json` 的 18.0 秒。FSBP 目前更可靠的价值主张是“以结构不变量阻止 annotation 进入下游，同时保留 raw 审计”，而不是已经得到实验证明的质量增益。

正序与逆序裁判的首选一致率仅为 35.0%（7/20），说明模型裁判噪声和位置敏感性很高。后续应扩大样本、改进压力构造，并加入专家人工盲评。完整数据见 `experiments/results/2026-07-24T15-25-09-239Z-e5ee2aaa/`，自动生成的 Markdown/HTML 报告见 `experiments/reports/2026-07-24T15-25-09-239Z-e5ee2aaa.*`。

## 7. 威胁与局限

- 模型裁判可能偏好自身文风，交换顺序只能缓解位置偏差。
- 20 个样本适合工程消融和失败分析，不足以代表全部语种与领域。
- FSBP 隔离显式 annotation，但不能识别正文中伪装成译文的元指令。
- token 估算不是各供应商精确 tokenizer；未配置 contextWindow 时只能警告。
- 拼音韵母和 CMU 近似韵脚不是古典或诗学权威。
- 法律/医学等输出不能替代专业审查。

## 8. 工程完整度

本轮交付把原型扩为包含数据迁移、协议、双向 Agent、服务端编排、审计版本、批处理、桌面发行、自部署和实验工具的完整系统。最终质量门禁以 `typecheck`、Vitest、Next build、Playwright、Windows 打包与 Docker 健康检查为准；实际执行状态应以开发交付记录为准，不在报告中预先宣称通过。
