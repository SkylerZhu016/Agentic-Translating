# Agentic Translating vNext 技术报告

## 摘要

本项目定位为“面向高难文本的多方案翻译决策台”，覆盖文学、诗歌、规范文本、学术技术文本等没有单一标准答案的双向翻译任务。系统不把多个 Agent 当作独立任务的并行执行器，而是将它们视为针对同一问题、持有不同观察角度的候选生成器。主 Agent 负责选角、比较、审议、融合和版本化修改。核心方法 FSBP 由自由文本、阶段正文语义契约、最后一个独立 `---` 边界、raw 留档，以及正文与注释的显式分离共同组成。工作流默认只继承正文，也允许用户明确选择把注释作为不受信任的辅助材料传入下游；分歧地图始终只比较正文。

vNext 新增 10 个原型、20 个中英方向变体、双向提示词包、动态/固定组队、两条成稿路径、证据化编辑、revision 预设、批量队列、历史恢复、Windows Electron 与 Docker 自部署。第四次迭代进一步加入分歧地图、项目级翻译档案、首次运行向导与端点兼容性医生，以及基于真实调用记录的本地统计。这些能力共享候选、版本、项目快照和调用账本，避免形成互不相干的功能孤岛。

## 1. 问题定义

翻译涉及多义解析、目标语自然度、作者声音、文化负载、术语一致性、长距离连贯和形式约束等多个维度。单一模型的一次输出往往将这些目标折合成一个未经比较的妥协方案。多模型和多提示词能扩大候选空间，但如果缺少可审计的融合过程，用户仍然无法回答"为什么改成这样、依据来自哪里"。

本项目因此同时解决四个问题：

1. 如何低成本地产生有意义的候选差异，而非随机的变化；
2. 如何让审议过程接收完整证据，又不被候选注释锚定；
3. 如何把最终修改保存为可查看、可撤销、可复现的版本历史。
4. 如何把候选分歧、长期翻译决定与真实运行成本转化为用户可以检查和复用的产品资产。

## 2. 方法

### 2.1 角色化候选

10 个原型覆盖基础、表达、领域、创意和对抗视角。主 Agent 的常驻上下文仅包含简短目录，调用时才注入角色的完整提示词。后端保证至少两个不同原型的成功候选，当动态选择失效时执行"忠实 + 自然"的保底策略。

### 2.2 FSBP

模型返回完整的自由文本。系统保存 raw 内容，并解析出正文 body 与 annotation。默认策略只把 body 传给后续 Agent；用户也可以在工作流预设中显式选择 `body_and_annotation`，把分离后的注释作为需要独立核验的辅助材料传递。协议不规定固定字段，但规定阶段正文的用途：审查正文承载错误与风险证据，筛选正文承载保留与修补决定，编排正文承载完整工作译文，组装正文承载正式译文。过程说明与自我评价进入 annotation。精确的状态变更仍由少量工具 JSON 完成。

### 2.3 双向提示词

英译中的编排链使用中文提示词，中译英链使用英文提示词；用户任务要求原样作为用户数据处理。方向和提示词包在会话创建时冻结，不能原地反转。

### 2.4 证据化编辑

`write_draft` 需要至少两个候选 invocation。`replace_text` 校验当前版本、唯一匹配和事务一致性，创建 Patch 与不可变的新版本。Unicode grapheme 差异用于界面标记，失败时退化为块级对照。

## 3. 系统设计

服务端拥有运行任务，SSE 只是可重连的订阅通道。事件带递增序号并落库，浏览器离开不会取消运行；启动时遗留的 running 标记被置为 interrupted。配置快照冻结实际的端点与模型绑定，公共 DTO 只暴露端点摘要和 `hasApiKey`。

SQLite 保存会话、候选 raw/body/annotation、阶段输出、工具事件、版本、Patch、草稿、预设 revision 与批次。旧 schema 保留只读兼容，迁移不做破坏性删除。

### 3.1 分歧地图

分歧地图是服务端确定性派生视图，不新增翻译阶段，也不修改候选正文。系统按段落、句子或诗行切分候选，仅使用 FSBP `body` 参与比较；`annotation` 不进入候选集合哈希、对齐或返回结果。地图突出措辞、标点、数字、否定、专名、术语和结构差异，并同时展示对应原文、候选来源与当前最终译文片段。

这些标签描述机械差异，不判定翻译正误。对齐不可靠时接口仍返回可用的全文比较视图，地图故障不会阻塞翻译或提交。用户采用某个片段时，界面将请求交给既有编辑 Agent，继续通过 Patch、TextVersion 和证据链落版；它不会绕过版本系统直接覆盖正文。

### 3.2 项目级翻译档案

翻译项目用于积累术语、专名、人物声音、风格规则、已确认决定、背景说明、平行语料和反例。资源拥有稳定身份和追加式 revision。新建资源及 Agent 建议保持 `suggested` 或 `pending`，只有用户批准后才会进入新的不可变项目快照，拒绝操作同样保留审计记录。

会话可冻结项目、快照、实际资源 revision 和 token 估算。冻结内容以独立用户数据块进入模型上下文，不写入系统提示词；之后修改项目不会改变历史会话。方向、范围、快照成员和内容哈希在服务端校验，公共接口不会返回端点凭据。该设计把长期一致性从隐式“自动学习”改造成用户可批准、可追踪的翻译资产。

### 3.3 首次运行向导与端点兼容性医生

首次运行状态保存在 SQLite，而非只依赖浏览器存储。兼容性医生以短请求检查模型列表、普通对话、真实流式响应和工具调用，并分别记录这些结果；标准 usage 是否可用由普通非流式响应同时判断。单项不支持不会抹掉其他已经得到的结果。探测档案具有有效期，端点地址或密钥修改后会失效，错误信息在保存前移除凭据。

只要普通对话可用，用户仍可创建工作流。缺少真实流式响应会显示体验警告；缺少工具调用时，工作流退化到经典四阶段。快速、均衡和深度三个选项最终写成普通的用户预设 revision，可以继续编辑、复制和删除，不建立隐藏的系统工作流。界面同时说明配置和历史保存在本机，但调用远程端点时任务内容会发送给该端点。

### 3.4 LLM 调用账本与本地统计

`llm_call_records` 覆盖 vNext 编排链中的每次实际物理请求与重试、编辑对话、三镜头修订建议、兼容性医生的 chat/stream/tools 探测，以及已保存 Agent 和未保存提示词预览的独立测试。它记录状态、操作类型、模型、端点引用、重试次数、首包时间、总耗时和可获得的 token。模型列表查询只是元数据读取，明确不计作 LLM 调用。usage 来源区分供应商返回、本地估算和未知。数据结构也能区分供应商返回、本地价格快照估算和未知费用；只有调用方确实提供可核验费用或价格快照时才会出现已知费用，当前运行中费用通常保持未知。账本不保存 prompt、原文、译文、完整端点 URL 或 API Key。

历史页只展示由账本聚合出的已记录 LLM 调用数、已知 token、平均首包与总耗时，以及账本中确实存在的已知费用。缺失数据保持“未知”，不会补造。该统计不包含模型列表查询、普通页面请求或其他非模型操作，也不是供应商账单，不应与供应商最终结算金额等同。

## 4. 产品交互

顶栏方向开关不增加导航层级。当存在非空草稿或现有会话时，切换弹窗明确说明旧进度已保存；"不再提示"只在确认切换时持久化。两个方向各有一个 SQLite 草稿。

新增界面复用既有 Card、Badge、Modal、Button、Textarea、Spinner 和纸墨色板。分歧地图嵌入最终译文与证据区；项目档案、首次向导与兼容性医生位于配置页；调用统计位于历史页。它们不增加顶层导航，也不改动主体双栏骨架。

## 5. 确定性检查

后端检查段落/分节、非空行、必需/禁用词、结构、数字、单位和专名遗漏提示。诗歌额外提供：

- 英译中：汉字数、五七言倾向、末字与普通话拼音韵母；明确不等同于平水韵裁决。
- 中译英：行数、词数、末词与 CMU 词典近似韵脚；未知专名标为未知，仅作现代英语发音辅助。

检查器不修改、不拒绝候选，只将自然语言证据交给审议 Agent。

## 6. FSBP 验证计划

早期试运行使用的样本、执行器和结果已经退役，不能作为新版架构的质量
证据。新版验证在 `FSBP_Test/` 中重新建立，并将三个问题分开：

1. JSON 与 FSBP 的协议可靠性；
2. raw 与 body-only 的注释隔离效果；
3. 直接翻译、多 Agent raw、多 Agent FSBP 的端到端质量。

数据集现包含 8 个开发样本和 16 个结构锁定测试样本，共 24 项，按方向及
四类高难文本均衡。注释压力样本只能来自正常调用中自然出现并经人工确认的
实际错误，不得人工编造误导注释。由于其中部分文本后来参与了提示词与工作流
迭代，现有结果只能作为开发证据，不能作为未见集泛化结论。正式质量声明需要
重新冻结此前无人查看、未参与调参的独立留出集。

## 7. 威胁与局限

- 模型裁判可能偏好自身的文风，交换顺序只能缓解位置偏差，无法彻底消除。
- 公有领域与开放许可要求会造成一定年代偏差，数据集也不能代表全部语种与领域。
- FSBP 能隔离显式 annotation，但无法识别正文中伪装成译文的元指令。
- 分歧地图依赖确定性分段与对齐，只能指出候选不同，不能证明某个候选正确；复杂长文本可能退化为全文比较。
- 项目档案的质量依赖用户审批。未批准建议不会影响会话，这同时意味着系统不会自动吸收每次修改。
- token 估算并非各供应商的精确 tokenizer；未配置 contextWindow 时只能发出警告。
- token 覆盖率取决于端点返回值；只有调用方提供可核验金额或价格快照时费用才会已知，当前请求通常保持未知。本地统计不能替代供应商账单。
- 拼音韵母和 CMU 近似韵脚不具备古典或诗学权威性。
- 法律/医学等领域的输出不能替代专业审查。

## 8. 工程完整度

本轮交付将原型扩展为包含数据迁移、协议、双向 Agent、服务端编排、审计版本、批处理、桌面发行、自部署和数据集校验工具的完整系统，并建立项目档案、端点能力档案、分歧派生视图与统一调用账本。2026-08-11 的候选源码门禁结果为：91 个 Vitest 文件、911 项测试全部通过；TypeScript 类型检查通过；standalone 生产构建、2402 文件发行树扫描和 migration 14 独立启动冒烟通过；Playwright 34 项中 21 项通过、13 项因旧手动工作流已被 v3 取代而明确跳过。单 Agent 重试还经过修复后的连续 10 次专项验证。Windows 安装包制作与 Docker 健康检查未在本次候选源码验收中重跑，因此本报告不把它们写成已经完成的本轮门禁。
