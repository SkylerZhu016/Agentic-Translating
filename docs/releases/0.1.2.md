# Agentic Translating v0.1.2

[中文](#中文) | [English](#english)

## 中文

0.1.2 是第四次产品迭代后的首个稳定候选版本，进一步明确了“面向高难文本的多方案翻译决策台”定位。本版本继续保留 FSBP 自由文本协议、双向模式、动态或固定组队、经典四阶段和证据化编辑，并增加三个相互关联的产品能力。

### 新功能

- **分歧地图**：按段落、句子或诗行对齐候选正文，突出措辞、标点、数字、否定、专名、术语和结构分歧。比较只读取 FSBP `body`，不会受 Agent 注释影响；无法可靠对齐时安全退化为全文比较。
- **项目级翻译档案**：保存术语、专名、人物声音、风格要求、已确认决定和背景说明。新内容必须经过用户批准才会进入不可变快照；会话冻结实际使用的资源 revision，后续修改不会改写历史任务。
- **首次运行向导与兼容性医生**：分别检查模型列表、普通请求、真实 SSE、usage 和工具调用，允许在部分能力不可用时给出诚实的兼容方案，并生成归用户所有的工作流预设。
- **本地调用统计**：统一记录真实物理请求、重试、首包时间、耗时和可获得的 token。缺少供应商 usage 或可信价格依据时保持“未知”，不会冒充供应商账单。

### 稳定性与安全

- 会话创建加入 canonical SHA-256 请求指纹；同一幂等键携带不同任务内容时明确拒绝，不会生成重复会话或误清草稿。
- 浏览器断开、流读取取消和应用重启会关闭上游请求或收口账本状态，避免任务永久显示“运行中”。
- 翻译、四阶段、聊天、修订建议、Agent 测试、会话详情和导出统一使用安全错误码与诊断 ID，不向浏览器、日志或新数据库记录暴露供应商错误中的密钥、完整 URL、原文或提示词。
- 删除端点改为“检查引用 → 分类摘要 → 解绑并删除”。用户 Agent、提示词、模型、上下文窗口与冻结历史继续保留。
- 修复同一秒内重试记录按随机 UUID 排序的问题。成功重试不再偶尔被旧失败记录覆盖；该路径在修复后连续验证 10 次全部通过。
- 官方 Agent 升级继续受到所有权保护，不会修改或删除用户自定义 Agent。

### 验证

- Vitest：91 个文件、911 项全部通过；
- TypeScript 类型检查：通过；
- standalone 生产构建、2402 文件发行树扫描及 migration 14 独立启动冒烟：通过；
- Playwright：21 项当前流程通过，13 项旧手动流程夹具明确跳过；
- Windows 安装版与便携版均由同一份 0.1.2 源码构建。

### 已知边界

- 当前发布仅提供 Windows 二进制文件，其他系统需要从源码构建。
- 项目资源暂不支持 retire/restore；Patch 也不会自动写回项目档案。
- 批量任务暂未绑定项目 snapshot，输入仍限 UTF-8 TXT 和 Markdown。
- EPUB、DOCX/CAT 互操作、高级历史搜索和项目趋势图留待后续版本。
- 本版本的工程门禁不等于正式翻译质量实验结论；FSBP 是否在未见集上优于直译仍需独立评审。

## English

Version 0.1.2 is the first stable candidate after the fourth product iteration. It strengthens the product's position as a multi-option translation decision workbench for difficult texts while preserving FSBP free-form output, bidirectional modes, dynamic or fixed teams, the classic four-stage workflow, and evidence-based editing.

### New capabilities

- **Disagreement map:** aligns candidate bodies by paragraph, sentence, or poetry line and highlights differences in wording, punctuation, numbers, negation, proper nouns, terminology, and structure. It reads only FSBP `body` content and safely falls back to full-text comparison.
- **Project translation memory:** stores terminology, proper nouns, character voice, style rules, approved decisions, and context notes. User approval creates immutable snapshots; sessions freeze the exact resource revisions they use.
- **First-run guide and compatibility doctor:** probes model discovery, ordinary chat, genuine SSE, usage reporting, and tool calls separately, then creates user-owned workflow presets from the verified capabilities.
- **Local call analytics:** records physical requests, retries, first-byte latency, total latency, and available token usage. Missing provider usage or trustworthy price data remains unknown rather than being presented as a provider bill.

### Reliability and security

- Session creation now uses a canonical SHA-256 request fingerprint to distinguish safe idempotent replay from conflicting task content.
- Browser disconnects, stream cancellation, and application restarts close upstream work or settle ledger records instead of leaving permanent running states.
- Translation, stages, chat, revision suggestions, Agent tests, session detail, and exports use controlled error codes and diagnostic IDs without exposing keys, full URLs, source text, or prompts from provider errors.
- Endpoint deletion now follows “inspect references → review grouped summary → detach and delete”. User agents, prompts, models, context settings, and frozen history remain intact.
- Fixed a same-second retry ordering race where a successful retry could be replaced by an older failed record. The repaired path passed ten consecutive repetitions.
- Built-in Agent updates remain ownership-safe and never modify or delete user-created Agents.

### Validation

- All 911 tests in 91 Vitest files passed.
- TypeScript validation passed.
- The standalone production build, 2,402-file release-tree scan, and isolated migration-14 startup smoke passed.
- Playwright reported 21 active workflow passes and 13 explicit skips for superseded legacy manual fixtures.
- Both Windows artifacts are built from the same 0.1.2 source revision.

### Known boundaries

- This release provides Windows binaries only; other platforms must build from source.
- Project resources do not yet support retire/restore, and patches are not automatically promoted into project memory.
- Batch jobs do not yet bind a project snapshot, and input remains limited to UTF-8 TXT and Markdown.
- EPUB, DOCX/CAT interoperability, advanced history search, and project trend views remain future work.
- Engineering gates are not a formal translation-quality result. FSBP still requires independent evaluation on a genuinely unseen set before claiming superiority over direct translation.
