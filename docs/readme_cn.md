# Agentic Translating · 智能体翻译工作台

[**中文**](#) | [**English**](../README.md)

面向个人使用的复杂中英翻译工作台。提交一次原文，在有调用上限的流程中比较不同角色的候选，完成审议并得到完整译文。

**最新版本：[v0.2.0](https://github.com/SkylerZhu016/Agentic-Translating/releases/tag/v0.2.0)**——提供 Windows 安装版和便携版，其他系统可从源码自行构建。更新内容见[发行日志](releases/0.2.0.md)。

下文的 JSON 内容契约、综合审查、角色输出预算、外观主题和有限推理预览及流式显示改进属于当前源码更新，尚未制作新的发行包。v0.2.0 下载文件包含的功能以其发行日志为准。

多个角色处理同一份原文，候选之间的分歧作为审议证据保留。默认流程依次完成审查、筛选、编排和组装，调用次数受配置约束。工具协作作为探索性选项保留，日常体验围绕清楚的进度、便捷的阅读修改和可恢复的版本展开。

## 核心能力

- 支持英译中和中译英双向模式。会话创建后方向冻结，两个方向各自保存独立的工作台草稿。
- 10 个 Agent 原型，每个有 2 个方向变体：忠实、自然、声音、术语、文化、长文本、规范文本、文学、诗歌、异议。
- 动态组队和固定预设两种模式并存。第一版形成前，系统至少保留两个不同原型的成功候选。
- 新工作台默认采用“审查、筛选、编排、组装”四阶段流程，工具协作作为可选的探索性成稿方式。
- 分歧地图按段落、句子或诗行对齐候选正文，突出措辞、标点、数字、否定、专名、术语和结构差异。它是确定性的比较辅助，不会自动判定哪份译文正确。
- 项目级翻译档案用于维护术语、专名、人物声音、风格规则、已确认决定和背景说明。新条目先作为建议保存，只有用户批准后才进入不可变快照；会话可以冻结该快照。
- 首次运行向导与端点兼容性医生分别呈现模型列表、普通对话、真实流式响应、usage 和工具调用的检查结果。快速、均衡、深度工作流都会成为用户拥有的普通预设 revision。
- 隐私安全的 LLM 调用账本覆盖 vNext 编排链中的每次实际请求与重试、编辑对话、三镜头修订建议、兼容性医生的 chat/stream/tools 探测，以及 Agent 独立测试。它记录状态、已知 token、首包时间和总耗时；缺失 usage 时保持“未知”。模型列表查询属于元数据读取，明确不计作 LLM 调用。
- 新内建提示词使用 JSON，明确区分正文 `body` 和注释 `annotation`。内容通道的原始响应保留存档，供应商推理走独立的有限实时预览。旧 FSBP 预设和历史记录保持原有冻结行为。
- 探索性的工具协作模式分阶段开放 `call_agents`、`write_draft`、`replace_text`、`submit_final`，每轮只注入当前需要的工具。
- 版本化修改、Unicode 修订对照、证据引用、撤销与恢复。
- 用户预设版本管理、历史恢复、安全导出，支持最多 100 个文件的批量队列。
- SQLite 本地优先存储，支持 BYOK 和 OpenAI 兼容端点。API Key 不会出现在浏览器 DTO、SSE 事件、日志或导出文件中。
- 提供 Next.js Web 版、自部署 Docker 版、Windows Electron 安装版和便携版。

英译中默认产出普通中文。五言、七言、押韵等格式属于任务要求或诗歌 Agent 的专门约束，不作为系统默认行为。

## 快速开始

需要 Node.js 22.12.0 或更高版本。

日常桌面使用先准备一次生产构建：

```bash
npm install
npm run build:standalone
npm run desktop
```

之后也可以直接双击项目根目录的[启动翻译工作台.cmd](../启动翻译工作台.cmd)。更新源码后重新构建。首次使用时，“配置”页面会引导你添加 OpenAI 兼容端点、检查实际能力，并创建用户拥有的工作流。熟悉配置的用户也可以跳过向导，直接设置各项模型分工。

使用生产 Web 版：

```bash
npm run build
npm start
```

打开 `http://localhost:3000`。修改源码并实时查看变化时，再使用 `npm run dev`。

## 工作方式

1. 在右上角选择"英译中"或"中译英"。
2. 输入原文和自然语言任务要求。可以选择一个翻译项目，再选择允许的 Agent、预设和审议模式。项目中获批准的资源会随会话冻结，之后修改项目不会改写本次上下文。
3. 动态模式下，主 Agent 会调用 2 到 4 个适合当前文本的角色。如果没有有效的选择，自动启用"语义忠实 + 目标语表达"保底组合。
4. 默认流程完成四阶段审议并组装完整译文。在“生成进度”查看运行状态，在“译文编辑”阅读和修改成稿。
5. 使用分歧地图查看候选真正不同的位置。比较过程不读取 Agent 注释；无法可靠对齐时会退化为全文比较。
6. 后续修改必须通过精确文本工具创建 Patch 和新版本。候选片段可以沿用现有修订流程交给编辑 Agent 采用，继续保留修改前后对比、理由和证据。

切换方向不会转换现有会话。系统会先保存当前草稿，然后切换到另一个方向的工作台草稿。旧会话仍然保留在历史中，后台任务不会因为页面关闭而取消。

内置双向提示词包 v24 在四阶段流程中使用一次综合审查，同时检查忠实度与逻辑、自然度与声音、任务与文类约束。筛选阶段独立回查原文，组装阶段检查修改是否引入退步。冻结审查提示词中的独立行 `[review:integrated-v1]` 决定采用这条路径，旧有无标记会话继续运行三个独立审查，并要求至少两个成功。

## 外观设置

打开“配置 → 外观”，可以选择清爽蓝、柔和紫、暖灰珊瑚或石墨黑白。切换立即生效，并保存在当前设备上。每套主题都可以保留自定义主色，也能恢复原配色。过浅的主色会自动调整亮度，保证文字清楚，设置面板会显示实际应用的颜色。

## 结构化输出与流式显示

新内建提示词通过 `[protocol:json-v1]` 声明输出格式，要求恰好包含两个字段：

```json
{"body":"完整译文或当前阶段的交付内容。","annotation":null}
```

`body` 必须是非空字符串，`annotation` 为简短译注或 `null`。程序校验通过后才接纳候选和正式版本，残缺 JSON、重复字段或错误字段类型会明确失败。流式解析逐步解码正文，用户可以在生成结束前阅读译文。

使用客户端白名单中的官方 DeepSeek 模型和 Chat Completions 地址时，只有 system 提示词选择 JSON 格式，且请求没有工具与工具选择参数，客户端才自动添加 `response_format: {"type":"json_object"}`。第三方网关保持原有请求格式，具体匹配条件见[协议规范](protocol-spec.md)。

供应商提供的 `reasoning_content`、`thinking` 和 `reasoning` 与这两个字段分开。界面仅保留有限的最近推理片段，历史保存字符数等诊断信息。长文本面板同时限制高度与实际渲染量，通过分段翻阅查看内容，并可下载已经接收的正文。

下游默认继承正文，预设可以显式加入注释作为辅助材料。未包含新标记的冻结提示词继续兼容 FSBP，以最后一条独立 `---` 分隔正文和注释。更新程序会保留旧会话与预设版本。完整定义见 [协议规范](protocol-spec.md)。

## 预设与批量

预设是用户创建的可重复工作契约，不是系统替用户决定的翻译策略。每次内容修改都会建立新的 revision，历史会话和批次继续使用冻结时的快照。

角色默认配置和工作流预设都可设置输出预算 `maxOutputTokens`，每次调用中的思考与正文共用这一额度。填入正整数，或留空使用应用默认的 4,096 token。DeepSeek 长思考可尝试 32,768，具体按所选模型支持的上限调整。切换模型会保留已保存的预算，应按新模型重新核对。

批量任务必须选择一个有效的 revision。支持 UTF-8 编码的 `.txt` 和 `.md` 文件，支持 1 到 4 个并发任务、暂停和恢复、失败项重试、路径镜像、BOM 和换行符保持，以及 Web ZIP 导出。详见 [预设与批量](preset-and-batch.md)。

## 桌面与自部署

普通 Windows 用户可直接从 [v0.2.0 Release](https://github.com/SkylerZhu016/Agentic-Translating/releases/tag/v0.2.0) 下载：

- `Agentic Translating-0.2.0-setup-x64.exe`——推荐使用的安装版；
- `Agentic Translating-0.2.0-portable-x64.exe`——无需安装的便携版。

首次启动会创建本地应用数据；覆盖升级不会删除翻译历史或用户自定义 Agent。删除端点前，程序现在会展示其当前与历史引用，并可仅解除活动绑定，不删除 Agent 定义。

Windows 打包：

```bash
npm run package:win
```

日常使用时，先运行一次 `npm run build:standalone`，再运行 `npm run desktop`。桌面读取这份生产构建，运行时无需让开发编译器和文件监听常驻内存。修改源码后重新构建。缺少或尚未准备完整的产物时，应用会给出具体的准备命令并退出，由用户明确执行构建。`npm run desktop:preview` 保留为同一生产模式的兼容入口。

开发时使用 `npm run desktop:dev`，可以直接启动并实时查看代码变化，缓存写入 `.next-electron-dev`。普通 `npm run dev` 使用独立的 `.next-web-dev`，两个开发入口分别维护缓存。

产物位于 `dist-electron/` 目录，同时生成 NSIS 安装版和便携版。桌面版数据存储在 Electron 的 `userData` 目录，密钥由 `safeStorage` 封装的本地主密钥保护。

Docker：

```bash
docker compose up --build
```

生产 Web 部署必须设置 `AGENTIC_SECRET_KEY` 环境变量。构建、备份与升级说明见 [桌面与自部署](desktop-build.md)。

## CLI 测试驾驶舱

`scripts/dev-harness.mts` 通过纯命令行驱动工作台的核心会话、HTTP、SSE 与
对话修订操作（需要 Node.js 22.12+）。请先启动应用，并明确传入应用实际端口：

```bash
npm run harness -- --help
npm run harness -- list --base=http://127.0.0.1:3000
```

子命令：`create`、`run`、`translate`、`events`、`chat`、`suggest`、
`state`、`list`、`rm`、`restore`。它直接复用项目自己的 SSE 解析器，并有
独立的协议终态自动测试。特点：

- 增量 SSE 输出带时间戳和阶段标签；`--trace` 在 `FSBP_Test/private/debug/` 下
  落盘 JSONL 日志。
- 失败时自动转储最近 50 条事件和会话状态并以非零码退出。
- `suggest` 只生成只读修订建议，由相互隔离的目标语读者、双语核验者和
  仲裁者三镜头组成；需要真正落版时再使用 `chat`。
- `create --request-id=<UUID>` 支持幂等重试；`run` 与 `events` 可重新连接服务端
  持有的任务和已经持久化的事件流。

测试驾驶舱不复刻配置表单和批量文件选择。浏览器仍用于布局与视觉回归；
核心模型流程验证可以完全在命令行完成。

## 当前范围

内置能力集中在通用高难翻译与诗歌相关任务，其他领域可以由用户增加自定义 Agent 和提示词包。批量输入目前支持 UTF-8 `.txt` 和 `.md`。EPUB 支持明确延期：后续应评估成熟且许可证合适的解析与回写方案，不从零重做完整格式处理。

v0.2.0 的历史验收记录包括 119 个文件中的 1,180 项 Vitest 检查、TypeScript 校验、migration 18 standalone 生产启动冒烟，以及覆盖双向草稿与响应式国际化的 17 条浏览器流程。当时的 Electron 源码开发版和生产预览版还完成了首次启动、持久化、弹窗、窄屏、历史页与导出入口验收。

当前源码已包含 migration 19，本轮此前的一次完整测试记录为 1,416 项 Vitest 测试通过。后续局部回归验证单独记录，保留该次全量统计的原始计数。这些记录对应各自受测版本的工程验证，正式翻译质量评价尚未完成。

## 数据与安全

- Web 开发环境数据库默认位于 `data/app.db`。
- Electron 将数据库、日志和运行文件存放在应用的 `userData` 目录。
- 开发环境可以生成仅供本机使用的密钥文件。生产环境不会自动生成弱默认密钥。
- 删除会话、预设和批次前需要界面确认。预设默认采用软删除。
- 旧会话和旧预设表保留只读兼容性，迁移时不做破坏性删除。
- Agent 提出的项目资源永远不会自动批准；历史会话继续使用当时冻结的项目快照。
- 本地统计概览只返回白名单聚合，不包含提示词、原文、译文、完整端点 URL 或 API Key。数据结构能够区分供应商返回、本地估算和未知费用，但只有调用方提供可核验金额或价格快照时才会出现已知费用；当前请求通常保持“未知”，该概览永远不能当作供应商账单。
